# Tool Integration Architecture (TIA-1)

**Version**: 1.0  
**Status**: Approved  
**Author**: Chief Platform Architect  

---

## 1. Objective
This specification establishes the boundaries, sandboxing wrappers, and execution lifecycle for external tools integrated into the HSCI V5 runtime. It ensures that the cognitive orchestrator can execute utility tasks without introducing side effects or security vulnerabilities into the host environment.

---

## 2. Tool Execution Boundaries

```
[BrainKernel] ──► [WorkingMemory] ──► [ToolRegistry] ──► [ToolExecutor]
                                                            │ (gRPC API)
                                                            ▼
                                                     [Sandboxed Worker]
                                                     (Subprocess/Docker)
```

No tool may run in the same process namespace as the main cognitive thread. All executions must follow strict isolation boundaries.

---

## 3. Sandboxing & Wrappers

### 3.1 Subprocess Isolation
On single-node runtimes, tools are executed in isolated processes using restricted user accounts:
*   **Time Limits**: A maximum timeout of 5000ms is enforced on all external processes.
*   **Resource Limits**: Maximum heap allocation is restricted to 256MB.
*   **AST Pre-Scanning**: Any command string generated by the agent is parsed using AST filters to block unauthorized command injection patterns.

### 3.2 Containers & WebAssembly
For untrusted external code compilation tasks:
*   The execution is routed to a lightweight **WebAssembly (Wasm) runtime** or a read-only sandboxed container.
*   Disk write access is forbidden; all intermediate file states are held in memory-mapped buffers.

---

## 4. Tool Schema Registry
All tools must register their inputs using strict JSON schemas:
```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "CalculatorTool",
  "type": "object",
  "properties": {
    "expression": {
      "type": "string",
      "pattern": "^[0-9\\+\\-\\*\\/\\(\\)\\s\\.]+$"
    }
  },
  "required": ["expression"]
}
```
If a payload fails schema validation, the execution is blocked before calling the sandbox.
